A live window into every project

A secure portal that shows investors how their multifamily development projects are going, from permitting through lease-up: schedule, budget, financing, leasing, returns and photos.

Project managers keep the data up to date in an admin workspace. Investors only see projects they're assigned to, and only data a manager has reviewed and published.

The problem

Investor updates used to be put together by hand each quarter from spreadsheets, PDFs and email threads. That took managers a lot of time, gave investors no view of progress between reports, and made it easy to send a half-finished budget or draft schedule by mistake.

The key design decision was to separate editing from publishing. Managers can work on drafts freely. Investors see nothing new until a manager reviews a summary of what changed and publishes it.

What it does

  • Draft, review, publish. Each admin tab is a publishable section. Managers see a summary like "3 added · 2 changed · 1 removed" before anything reaches investors.
  • Investor reports. A report builder pulls data straight from the project tabs, adds manager-written commentary, and goes through an approval flow. A second admin has to approve each report. The finished report is frozen and saved as a PDF.
  • Scheduled release and email. An hourly job releases reports when they're due, emails investors with the PDF attached, and alerts managers if a release date passes with no report ready.
  • Budget import. Upload an Excel variance report and it's mapped onto the general-ledger account structure and merged with the previous report.
  • Leasing analytics. Weekly leasing funnel, unit mix, building deliveries, and lease-up curves compared with pro-forma, lender and revised forecasts. Investors can export a branded Excel workbook.
  • Returns and ownership. Project-level and per-investor returns with snapshot history, the capital stack, and an interactive ownership-structure diagram with documents attached to each entity.
  • Q&A threads and photos. Investors ask questions and managers post updates, each visible to everyone, only the asker, or chosen investors. Construction photos are stored privately and grouped by week.
  • Fine-grained access. Database-level security on every record, per-project investor assignment, and per-tab visibility toggles.

Architecture

The frontend is a single-page React app. The backend runs on a managed platform that provides the database, sign-in, private file storage, email, serverless functions and scheduled jobs. Anything that needs extra permissions or has to run without a browser, like imports, scheduled releases and emails, lives in serverless functions.

One place decides what investors can see

Every component reads data through the same SDK object, which I wrapped in a JavaScript Proxy. On admin pages, reads go straight to the database. On investor pages, reads come from the last published snapshot, filtered and sorted in memory to match the SDK's query API. Because the switch lives in one place, no investor page can show unpublished edits by accident, even when it reuses an admin component.

Publishing a section

Publishing compares the manager's current records with the last snapshot, then writes a new snapshot. The platform limits field size and has no transactions, so snapshots are stored as ordered JSON chunks. The new batch is written before the old one is deleted, and readers only use the newest batch. Investors never see a blank or half-updated section.

Investor report lifecycle

A submitted report must be approved by a different admin. Any edit after submission sends it back to draft and clears the approval. When a report is published, the app freezes its content and builds the PDF in the browser, so the scheduled job, which has no browser, only needs to attach the stored file.

Data model and access control

The backend has 37 entity types. Everything project-specific hangs off Project, and each entity has its own security rules based on the user's role and the project's investor and manager lists.

Technical highlights

  • Safe by default. Investor pages don't have to remember to read published data. The proxy makes that the default.
  • Consistent publishing without transactions. Writing the new snapshot before deleting the old one, and always reading the newest batch, keeps investor views consistent.
  • Print-quality PDFs. A custom layout step picks page breaks so tables, KPI cards and photos are never split across pages.
  • Time-zone-aware scheduling. Release dates are worked out in each schedule's own time zone, handling daylight saving time and short months (for example, the 31st in February).
  • Spreadsheet import. The variance importer cleans up messy Excel exports, matches rows by account code and then by name, and merges new actuals into the previous report.
  • Accurate forecasts. Lease-up math only counts a building as delivered once it actually has its certificate of occupancy, so forecasts aren't inflated by planned dates.

Outcome

A manual quarterly process became a continuously updated portal with a review step before anything is published. Investor reports are built from data that's already in the system and go out on schedule without anyone stepping in. The company decides exactly what each investor sees, down to individual tabs, metrics and threads.

About 25,000 lines of application code: ~140 feature components, 37 data entities and 7 serverless functions. Project data is confidential, so this page shows the architecture rather than screenshots.
